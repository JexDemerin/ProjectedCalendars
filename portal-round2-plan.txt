Parts:
1) Client record form: Mother/Father fields saved as "Mom: ..."/"Dad: ..." lines in Phone (D) and Email ID (E).
   Primary + Secondary caregivers saved to a new "Client Caregivers" tab. Schedule day boxes plus "Specific" in
   Schedule (M). Posting schedule (N) gets a "Copy from schedule" button.
2) Current Status sync, both ways, by UCI. Fixed label list; newest change wins; portal changes are logged as "Portal".
   The CRM gets a new endpoint (x-crm-secret) for the portal to add/remove labels, and pushes its own changes
   to the portal's crm-client-status.
3) Client Caregivers -> portal crm-client-caregivers (on save and on /api/sync). Send the UCI, child name and both
   parent emails.
4) WellSky visits -> portal crm-work-record (caregiver email, UCI, date, start/end, WellSky status). The portal does
   the counting. List names that don't map to a caregiver. Skip isDummy.
5) Enroll to portal -> crm-enroll-caregiver (first name, last initial, email, phone digits). The temp password lasts
   7 days; pressing again issues a fresh one.
6) Keys: caregiver = email, child = UCI.
7) Spreadsheet: never "Make a copy". The Apps Script stays as is.

Sibling care (new): add a rule to every visit sent in crm-work-record, matching what the CRM and the
ShiftVerification script already do (src/lib/day-hours.ts):
- Same caregiver + same day + EXACTLY the same start and end on two or more children = sibling care
  (one rate). The caregiver's hours count once (Naeem + Yusuf 5-7pm with Savanna = 2h for Savanna).
- Any difference, even 1 minute (5:00-7:00 and 5:01-7:01), means 1:1 care. The caregiver's hours count for
  each child (4h for Savanna).
- In both cases, each child consumes their own full hours (Naeem 2h, Yusuf 2h).
- Each visit carries sibling_group (a shared id for the group, else null), so the portal can show it the
  same way.

Weekend matching (Oct 21): a child can be matched for weekdays and still need weekends. The portal sends
active_shifts and open_shifts with each event. A match keeps the open-shift labels while open_shifts > 0;
an unmatch removes Active only when active_shifts = 0.

Portal answers (Oct 21): one open shift per child. "Mark as started" asks if it covers all care; No → shift stays
open (Partly covered), event shift_started with open_shifts 1 and posting_schedule = what's still open, which the
CRM writes into Posting Schedule. "Copy from schedule" also copies the Specific lines (one per line, no label).
